# concurv threat model

Scope: the local kernel (R1–R2.5), sync (R3), verified integration (R4),
agent coordination (R5) and the R6 additions (tags, configuration, Git
import into existing history), all implemented. Each row lists the mitigation **and
whether it is implemented**.

## Assets

Acknowledged history (objects, operations), uncommitted working files,
files outside the repository, credentials/tokens, agent transcripts and
private metadata, published branch heads (R3), relay private key and device
tokens (R3).

## Adversaries and mitigations

| # | Threat | Mitigation | Status |
|---|---|---|---|
| T1 | **Local attacker / buggy tool corrupts objects** (bit flips, truncation, edits in `.concurv/objects`) | every read re-hashes; `concurv verify --full`; corrupt dedup targets quarantined; fail closed | R1 implemented + tested |
| T2 | **Hostile object graph** (malformed headers, huge lengths, unsorted/duplicate entries, cycles, wrong kinds) | strict decoder, size limits before allocation, typed loads, kind check; trees are hash-linked so cycles are impossible without a hash collision | R1 implemented + tested |
| T3 | **Path traversal via tree names** (`..`, `/`, `\`, absolute, NUL, `.concurv`) | name validation on encode *and* decode; restore re-validates | R1 implemented + tested |
| T4 | **Symlink escape** (symlink in workspace makes restore write outside root; tree with `a` symlink then `a/b` file) | restore never follows symlinks: each parent checked with `symlink_metadata`; existing symlinks are removed, not written through; symlink targets stored as data only | R1 implemented; Unix symlink tests run only on Unix CI (not run on the Windows dev machine) |
| T5 | **Windows-specific names** (`CON`, `aux.txt`, `a:b` ADS, trailing dot/space, case collisions) | refused before any write on Windows; case-collision check on Windows/macOS | R1 implemented; tested on Windows |
| T6 | **Untrusted checkout path** (repository root inside a symlinked dir, `.concurv` replaced by symlink) | `.concurv` must be a real directory (checked with `symlink_metadata`) | R1 implemented |
| T7 | **Concurrent local writers** (many workspaces, agents and processes; processes killed mid-command) | workspace lock + commit-only repository lock with bounded waits; CAS on op_head against the current view; lock-free immutable object writes in per-process temp sessions that recovery never deletes while their owner lives; `main` moves only by fast-forward publish | R2 slice 2a implemented; tested with 2/5/10 concurrent writers and 12 rounds of killed processes on Linux, macOS and Windows |
| T7b | **One agent's workspace overwritten by another** | commands only change files of the workspace they run in; nested workspaces refused; merges happen in the private workspace, conflicts refused | R2 slice 2a implemented + tested |
| T8 | **Dirty working copy destroyed by restore** | refuse without `--force`; `--force` makes durable backup snapshot first; content re-check just before each replace | R1 implemented + tested; residual TOCTOU documented |
| T9 | **Malicious remote** (lies about heads, sends bad or incomplete objects, replays publishes, impersonates the relay) | pinned relay certificate (TLS 1.3; token sent only after the handshake); every received object re-hashed, size-checked before allocation and decoded; only blobs/trees/snapshots accepted; graph closure checked in quarantine before anything is adopted or referenced; relay branch names validated like local ones, collisions never create aliasing references; a relay head that does not descend from the one seen before is reported and not followed; publish request ids remembered by the relay | R3 implemented + tested (`hostile.rs`, `two_machines.rs`) |
| T10 | **Network replay / reorder / loss** (duplicate or reordered objects, lost publish replies, disconnects at any byte) | content addressing makes duplicates and reordering harmless; publish is a compare-and-swap with a client request id answered from the relay's memory on retry; quarantine is per connection and discarded on disconnect. Awareness events (TTL) are R5 | R3 implemented + tested (disconnect sweeps at every byte offset of a push and a fetch) |
| T11 | **Transcript / secret leaks** | no transcript capture at all in R1; future provenance opt-in, local-only by default, preview before publish | R1: nothing captured; author string is the only identity stored (from `CONCURV_AUTHOR` or OS user name) |
| T12 | **Arbitrary test code during validation** (a policy in the repository runs commands on every machine that checks it) | checks run only for a policy version approved on that device (`concurv check --trust`, by blob id; a changed policy needs a new approval; the commands are listed when refused); the policy must state `"sandbox": "none"` (no isolation, said out loud; unknown sandboxes refused); fresh directory outside the working copy, cleared environment with an allow-list, stdin closed, timeouts. Not yet: isolation (containers, VMs) | R4 implemented + tested (`verified_integration.rs`) |
| T13 | **Resource exhaustion** (huge files, deep trees) | limits in RFC 0001 §5; streaming blob IO; recursion depth bounded by OS path length | R1 partially (no depth/total-size quota yet) |
| T14 | **Untrusted Git repositories and the `git` tool** (hostile paths or entries in an imported Git history; a `git` from `PATH`; environment variables redirecting git) | import validates every path with the same rules as `save` (`..`, `.concurv`, invalid names refused) and refuses submodules and non-UTF-8 data, all-or-nothing; blobs are re-hashed into concurv objects; `GIT_DIR`, `GIT_WORK_TREE` and similar variables are scrubbed and every call uses `git -C <repo>`; export never moves a Git branch except by fast-forward CAS. concurv trusts the `git` binary found on `PATH` (same trust as running `git` yourself) | R2 slice 2d implemented + tested |
| T15 | **Ignored local files and colocated Git metadata** (an ignored `.env` or build cache overwritten by restore/update; `.git/` captured into history; a snapshot planting `.git/hooks` on restore) | ignored untracked files are never overwritten or deleted (refusal even with `--force`); `.git` never scanned; nested repositories skipped; restore refuses `.git` entries (and `GIT~n` on Windows). Ignore rules are **not** a secrets boundary: already-saved secrets stay in history (redaction is future work) | R1.5 implemented + tested (ADR 0004) |
| T16 | **False-clean status from a stale stat cache** (a changed file reported unchanged, e.g. same-size rewrite with the mtime put back, jj #10509; racy timestamps) | cache never consulted by `save`, restore, update, undo or checkout; Unix only, exact match on dev, inode, size, mode, mtime and kernel-set ctime; entries recorded only if identity is stable across the read and timestamps are outside a 2 s racy window; checksummed, any doubt = ignored; `--no-cache` | R1.5 implemented + tested (ADR 0005); residual risk on filesystems that do not maintain ctime |
| T17 | **Branch names that alias or break Git** (names differing only in case, `x` vs `x/y`, Unicode normalization variants, Windows device names, ref syntax such as `..` or `@{`, names shadowing remote-tracking refs) | Git's ref rules (differentially tested against `git check-ref-format`), ASCII-only portability policy, reserved `refs`/`remote`/`remotes`, component-wise case and prefix collision checks under the repository lock | R2.5 implemented + tested (ADR 0007 §5) |
| T18 | **Work lost when switching branches** (unsaved edits, untracked or ignored files overwritten, saves left on no branch, a crash midway) | refusals before any write; non-colliding untracked files kept; rollback on I/O error; marker + resumable switch after a crash; reachability invariant B1 | R2.5 implemented + tested (fault injection in crash and transient modes, killed processes) |
| T19 | **Stolen or leaked device token** (copied `.concurv/remotes/<name>/token`, token in shell history or CI logs) | tokens are 256-bit random, stored by the relay only as a keyed BLAKE3 hash, compared in constant time; failed authentication is answered after a fixed delay; scopes limit what a token can do (`read`, `write`, `publish:<branch>`); `concurvd device revoke`; on Unix the client's token file is owner-only; `CONCURV_REMOTE_TOKEN` avoids storing it. Not yet: token expiry, per-device key pairs | R3 implemented (revocation and scopes tested) |
| T20 | **Compromised or rolled-back relay** (relay restored from an old backup, relay operator rewrites `state.json`) | clients never follow a head that does not descend from the one they saw (`rewound`), and refuse to push to it; local branches and fetched history stay. A relay can withhold or delay publications (availability is not protected) and can show different devices different heads until they compare (no transparency log yet). Content addressing protects integrity, not authorship: snapshot signatures are R7 | R3 implemented + tested (rewound relay) |
| T21 | **Resource exhaustion of the relay or client** (many connections, slow clients, huge or endless uploads, huge packs) | at most 64 connections, idle timeout 120 s, messages ≤ 1 MiB, ≤ 10,000 objects per upload batch, blob size limit (default 4 GiB) checked before reading, structured objects ≤ 64 MiB, ≤ 1024 wants / 4096 haves per fetch; a client accepts at most 10,000,000 objects per pack. Not yet: per-device byte quotas, rate limits | R3 implemented (limits tested in `hostile.rs`); quotas open |
| T22 | **Forged, stale or misapplied attestations** (an attestation for another candidate, branch, policy version or OS; a result that contradicts the exit codes; a candidate that rewrites its own policy) | the policy comes from the branch's current head, never the candidate; attestations bind candidate, branch, policy blob, checks and OS, and are verified on every use; the decoder rejects a result that disagrees with the exit codes; at the relay only attestations vouched for by `attest` devices count. A runner can still lie about having run the checks: authenticity is device authentication, signatures are R7 | R4 implemented + tested (`verified_integration.rs`, `protected.rs`) |
| T23 | **Misleading or flooding intents; leaking through events** (a device declares intents for others, floods the relay, or events expose secrets) | intents are advisory only: no command refuses work because of one, so a false intent can at most cause a warning; each relay device can replace only the intents it submitted itself; at most 256 per submission and 4096 at the relay, validated (ids, sizes, names), expired ones dropped; events contain ids, names and the descriptions users wrote, never file contents, tokens or environment variables | R5 implemented + tested (`coordination.rs`) |
| T24 | **Configuration or tags used to mislead** (a planted configuration redirecting pushes or changing the author; a tag silently re-pointed at other code; a Git tag overwritten by an export) | configuration only supplies defaults (`author`, `remote`): it never relaxes a check, a refusal or a policy, and `.concurv/` is never versioned, so no repository, clone or fetch can bring configuration with it; unknown keys and malformed files are errors; tags never move (create refuses existing names, delete is recorded in the operation log with the old target, `undo` refuses both); `git export --tags` only creates missing Git tags in one transaction with the branch and refuses when Git has the name elsewhere; `git import --tags` refuses a concurv tag of the same name elsewhere | R6 implemented + tested (`config_cli.rs`, `tags.rs`, `git_ecosystem.rs`) |

## Out of scope

Compromised OS/kernel, hardware ignoring flushes, attackers with write access
to `.concurv` who also forge consistent hashes for their own content (content
addressing provides integrity, not authenticity; signatures are R7).
